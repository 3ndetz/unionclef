# 0.95.17 — obstruction-clearing honors break protection (G108 full-flood cell-loss)

Follow-up to 0.95.16. Fixes the remaining intermittent full-flood failure: the finished portal frame
was being corrupted during scaffold removal.

## The bug: an obstruction clear ignored break protection

`DestroyBlockTask`, when its target is briefly out of reach, clears whatever the reach ray is stopped
by — a RAW `CLICK_LEFT` swing that bypasses the planner/executor's break-protection chain
(`canBreakHook` → `BreakRules` → `shouldAvoidBreaking`) entirely. Its `canClear` gate only rejected
air, fluid, unbreakable, and the self-floor.

Measured on the nether portal (full flood): while removing the front scaffold, an out-of-reach
scaffold cell left the ray stopped by the top-row FRAME obsidian (the frame plane sits one block above
the scaffold top, with air in front). `canClear` let it through, so the bot mined a finished frame
cell for the full 9-second obsidian dig. The consequences cascaded: the frame was re-detected as
incomplete, the bot left to re-gather obsidian, and the churn drained the finite lava lake into
"Searching for a lava lake … Wander for Infinity" — a hard timeout. Ground truth: the top-row cell at
(2358,-53,358) went obsidian → non-obsidian over ~9 s while the only active task was scaffold removal.

- **`DestroyBlockTask.canClear`**: now refuses to clear a block the break-protection avoiders reject
  (`shouldAvoidBreaking`), the same check every other break path already makes. The intended TARGET is
  still dug freely; only an OBSTRUCTION the bot merely wants out of the way must respect protection.
  The bot repositions for a clean line instead of destroying the protected block. This is a general
  fix — `DestroyBlockTask` is a shared primitive (beds, portals, protected zones) and had ignored the
  protection system on every raw clear swing.

## How to test

```
OBS=1 python3 deploy/runner/nether_portal_test.py   # full flood -> gather -> build -> light
```

PASS = a real `minecraft:nether_portal` at the build, or the bot teleporting to the nether.

## Test results

Full-flood bench (real path: flood the lava lake -> mine obsidian -> build -> scaffold removal ->
light), ground truth by block id / dimension change:

- **0.95.16 baseline (no fix): 3/4.** The one failure was exactly this cell-loss — the frame cell at
  (2358,-53,358) mined during scaffold removal, then a re-gather that drained the lava lake into
  "Searching for a lava lake … Wander for Infinity" (a hard timeout).
- **0.95.17 (Fix 1): scaffold removal keeps the frame intact.** In the verified runs the removal
  phase completes with the obsidian count staying at 0 (no re-gather, no cell-loss) and "done
  constructing" following directly — the frame obsidian is no longer mined as an obstruction.
