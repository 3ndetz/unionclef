# 0.39.0

Fixes the frozen-camera bug (#29): a stuck mine/combat aim can no longer lock the
camera or survive a reconnect.

## Frozen camera / hard-stuck aim (#29)

The rotation smoother (`WindMouseRotation`) is a static singleton that steered the
mouse toward its stored target every render frame. If the task that set the aim died
without clearing it — a mine that got occluded, a combat lock that ended abruptly —
the camera stayed locked on that target forever. Being static, it even survived a
reconnect (the reported "camera still frozen after rejoining").

Two durable fixes, no band-aids:

- **Stale-aim auto-release.** `setTarget` now stamps a timestamp; the per-frame step
  releases the aim if nothing has refreshed it for 600ms. Every live consumer (mining,
  combat, walker, bow, bridge, pillar) refreshes the target every game tick (~50ms), so
  an active aim is never touched — but a dead task's aim clears itself within ~0.6s. No
  task can leave the camera frozen.
- **Reset-on-disconnect.** A `DISCONNECT` hook wipes all tungsten state (aim, running
  tasks, in-progress break, held keys) so nothing survives a re-join.
- The executor also releases the attack key + aim immediately when force-stopped
  mid-mine, instead of waiting on the timeout.

Tests: `stale_aim_test` (aim set by a dead task auto-releases within 2s),
`disconnect_test` (a running tungsten task is cleared after a forced reconnect).
