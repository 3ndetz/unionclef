# 0.94.0 — the tester build: tungsten-only, 1.21.11 made functional, and the repo cleaned up

This is the first build cut specifically for outside testers. It is a **snapshot of everything
that landed since 0.93.0**, verified to compile on all three MC versions and run on the stand.
Below: what the mod is, what changed, and — for each thing — **how to see it working**.

`v0.93.0` stays on GitHub as the untouched fallback. If any single change here turns out to
regress, it can be reverted on its own; nothing was squashed away.

---

## What this build is

Two systems in one JAR, each with its own chat prefix:

| Module | Prefix | What it does |
| --- | --- | --- |
| **Tungsten** | `;` | Movement — physics-simulated A* pathfinding, block-space search, bridging, mining, combat |
| **AltoClef** | `@` | High-level bot tasks (get items, kill mobs, survive, beat the game) |

**Baritone and Shredder are gone from the build.** They remain in the source tree for reference
only; nothing compiles or runs them. Tungsten is the sole pathfinder now, which is the single
biggest change of this cycle: the bot no longer runs two movement engines that fought each other.

The agent surface is exposed two ways: a **py4j** gateway (port 25333) and an **MCP server**
(HTTP, port 25350, bearer-token auth) — both call the same levers, so an external agent can drive
the bot directly (`getGameState`, `punk`, `gotoXYZ`, `buyByName`, `clickMenuByName`, …).

## Headline: 1.21.11 was quietly broken, and now works

The mod targets several MC versions from one source via a preprocessor. Several capabilities had
been **silently dead on 1.21.11** — they compiled, ran, and did nothing, because the 1.21.11 code
branch was an empty stub. Testers on 1.21.11 would have hit all of these. Fixed this cycle:

- **Wearing armour.** `isArmorEquipped` returned false for every piece and `EquipArmorTask` forced
  everything into the chest slot. On 1.21.11 the bot could not gear up at all — no armour means no
  surviving bedwars/skywars.
  **HOW TO TEST:** give the bot an iron set in its hotbar, run `@equip iron`, confirm all four
  pieces end up worn (head/chest/legs/feet). Automated: `python3 deploy/runner/equip_armor_test.py`.
- **The `@equip` command itself** never worked — on any version — since the repo was created: it
  read its argument list as the wrong type and threw on the first item.
  **HOW TO TEST:** `@equip diamond` (or `iron`/`gold`) with the pieces in the pack.
- **Crafting at a table** used a slow manual path because the recipe-book fast path was stubbed
  out on 1.21.11.
  **HOW TO TEST:** `@get diamond_pickaxe` (or any 3×3 recipe) near a table; it should craft.
- **Recovering after being kicked to the menu** (`GameMenuTaskChain` world-rejoin click) was a
  no-op on 1.21.11 — the bot would sit on the disconnect screen. Now it rejoins.
- **Tool selection** (`StorageHelper` garbage-slot / best-tool comparison) and two **input stubs**
  (sign typing, projectile-wall interaction) were also dead on 1.21.11 and are ported.

## Navigation (tungsten)

- **Pillar out of a pit.** When the bot dug or fell into a hole and its goal was up-and-to-the-side
  (a log on the surface), it stood at the bottom holding blocks it could have climbed with, until
  it died. It now towers out of the shaft to where the horizontal route reopens.
  **HOW TO TEST:** `python3 deploy/runner/pit_escape_test.py` (drops the bot in a 7-deep shaft with
  a side goal; it should pillar out). Toggle with `;settings pillarEscapePit false`.
- **The coarse search's "distance from start" was not a distance** (a copy-paste bug computed the Y
  and Z terms from the X coordinate), which let dead partial routes through and hid a counter. Fixed;
  nav is measurably steadier.
- **Route hand-off cleanups:** repeated-cell routes no longer truncate the movement queue, corner
  cuts that stranded the bot are refused, and an unreachable segment replans from the body's real
  position instead of a stale node.
  **HOW TO TEST the nav suite as a whole:** `python3 deploy/runner/run_suite.py nav` — 14 courses
  (flat, staircase, gaps, water, ladder, slime, break-a-wall, bridge, pillar-wall, hazard). All
  gate courses should pass on a healthy stand.

## Combat and the `@punk` agent scenario

The tungsten combat engine drives player-hunting; it is version-agnostic (no 1.21.11 stubs).

- `@punk <nick>` — A* approach + melee aura against one player. MCP: `punk`, plus `punkAny`
  (nearest of an allow-list, never hitting an avoid-list), `punkAvoid`, `punkStop`, `punkStatus`.
- `runAwayPlayer <nick> <dist>` — flee while keeping distance, never backing into the void.
- Fixes this cycle: sprint reset between hits, a slot-sync race that swung with the wrong held
  item, weapon selection from the hotbar (hold the sword, not the bow), and kite left/right logic.
  **HOW TO TEST:** `python3 deploy/runner/run_suite.py pvp` (needs two clients:
  `docker compose -f deploy/compose.test.yml --profile pvp up -d`), or `@punk <nick>` on a server.

## Code health

A full source audit ran this cycle: **~800 lines of dead code removed** (a whole unused voxel-cache
subsystem, dead pathfinder fields), and dozens of real correctness bugs fixed — `equals()`/`isEqual()`
contract violations that broke task de-duplication, reference-equality bugs on positions, an
unbounded BFS, inverted comparisons, and random-constructor off-by-ones. None change behaviour a
tester sees directly; together they remove a large class of "the bot does something bizarre once in
a while" faults.

Repo hygiene: 26 MB of committed test-run debris (stall dumps, recordings, session-state files) was
removed from version control.

## Known limitations — please report against these

- **The full `@gamer` playthrough does not finish yet.** It gets through early tools reliably and
  then stalls on the way to iron/nether. Terrain navigation and proactive block placement (bridging
  and pillaring as part of a planned route, rather than as a reactive recovery) are the active work.
  If you watch a playthrough, the useful report is **where** it got stuck (coordinates, what it was
  trying to reach).
- **Rendering on the CI stand is CPU-only** (software GL), so the automated playthrough runs slow;
  this is a bench limitation, not the mod.
- On heavily-modded servers the client can fail to load registries at join. Vanilla and lightly-
  modded 1.21 / 1.21.1 / 1.21.11 servers are the tested target.

## Install

Fabric Loader for the MC version in the release title, drop the JAR in `mods/`, launch. Everything
is bundled — no separate tungsten JAR.
