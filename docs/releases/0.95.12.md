# 0.95.12 -- the bot stops wedging on an unreachable canopy log (Finding B)

After a base-loss respawn (empty inventory) near a dark-oak canopy, the bot could fixate on a log
it cannot reach -- 6 blocks up, occluded by leaves, nothing in the pack to pillar with -- cycling
"reach route gave up" for 90+ seconds instead of leaving it and looking for wood it can actually
harvest. This is the post-death recovery wedge flagged after the cave-mob death report.

## Root cause

The block chooser picks the nearest breakable block that is not blacklisted, and "reachable" is
only "not blacklisted" -- there is no geometric check -- so an unreachable elevated log is a valid
target until it has been tried and condemned. The navigator's reach route DID give the log up and
report "given up 3 times in a row -- marking it unreachable", but that call allowed four failures,
so the verdict only counted as failure 1 of 5; the chooser then picked a neighbouring log, and the
canopy was never actually excluded. Even a per-block decisive verdict lost to the 45-second
cool-off: the first logs came back into the pool before the last were ground through.

## The fix

- A decisive give-up verdict now excludes the target at once, and the local same-type cluster with
  it (a canopy's logs are unreachable together), so the bot leaves an unreachable patch after one
  verdict and goes to explore for reachable wood. It stays evidence, not a permanent decision: the
  exclusion cools off after the usual window and the target is retried, and a genuine approach or a
  better tool restores it. The dig route (a movement goal into rock) stays per-block, so this never
  condemns rock a tunnel needs.

## Verified

Bench `deploy/runner/canopy_log_reach_test.py` (a leaf-occluded unreachable dark-oak canopy log,
empty pocket, no reachable log in range): before, the bot wedged the whole window; after, it
condemns the canopy in one verdict and goes exploring (PASS). Regression suite all PASS:
canopy-recovery variant (takes a reachable column, 13 s), tree_reach (log from the ground, no
pillar), canopy_drop (towers to a drop), self_floor_dig (cobblestone in 3.2 s), shaft_exit (out of
the shaft in 6.6 s).

To try it: give the bot an empty inventory under a tall tree / canopy with no reachable log nearby
and `@get oak_log 1` -- it should give the unreachable logs up and wander to find a reachable tree,
not spin on one spot.
