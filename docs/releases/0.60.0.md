# 0.60.0 — pipelined navigation: plan cheap, walk now, compute the next leg while moving

Navigation used to compute a whole physics path before pressing a single key, and the search
deliberately slept while the executor walked, so the bot stood still while the machine thought.
This release overlaps the computation with the movement.

## Fast-first navigation (default ON)

- **`FastPlanner`** — a baritone-class A* over block cells: a fixed move set (traverse, diagonal,
  ascend, descend, parkour) instead of a blind radius-8 scan, real g-cost accumulation with an
  admissible octile heuristic (3.563, just under sprint speed), an array binary heap plus an
  open-addressing long map (no per-edge allocation), time-sliced with a best-so-far result.
- **`FastNavigator`** — walks the current leg while the NEXT leg is planned **from the tail of the
  one being walked**, so the hand-off costs nothing and the search never blocks the bot.
- **Parkour is preserved.** A waypoint the planner flags as needing a real jump ends the walked leg
  and the physics engine takes that segment. When a plan dead-ends without approaching the goal
  (slime drop-bounce, hard parkour) the navigator stands down entirely and lets the physics search —
  already running in parallel — own the route.
- Toggle: `;settings fastBlockFirst false` (default true), budget `fastPlanBudgetMs` (default 250).

## Measured on the stand

| | tungsten fast-first | old physics-first | baritone/shredder |
|---|---|---|---|
| time to first movement | **0.65 s** | 2.4–3.6 s | 0.67–1.26 s |
| time to goal (85-block obstacle course) | **13.5–15.7 s** | 18.6 s (once never) | 16.4–18.1 s |

Reproduced across four runs. FPS while navigating: **12.1 → 21.4** average (renderer objects built
during a search: 119 → 0).

## Also in this release

- **Real block-space passability** (`PlayerFit`): the search now measures the actual 0.6×1.8 body
  against actual collision shapes, so a gap capped by a slab (1.5 blocks of real clearance) is no
  longer planned through. Regression test `slab_hole` covers it.
- **Renderer production is gated, not just the drawing** — objects were allocated into collections
  shared with the render thread even with visualisation off, once per expanded search node.
- New levers: `getPerfStats()` (fps + renderer count + engine state), `resetTungstenConfig()`,
  `respawnPlayer()`.

## Known state

- Slime parkour: `A_drop_bounce` stable; `B_short_bounce` flaky (1 of 3 warm runs).
- Real-terrain chase (`chase_terrain` on the world generator) still fails — the chaser mines into a
  hillside and stalls. Next focused pass.
- Bow-flee/kite primitive still missing; edge duel still loses footing under knockback.
