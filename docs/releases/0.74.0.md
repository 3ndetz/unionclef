## Flight had no plan B, and the bot died standing still

A skeleton twelve blocks away shoots the bot below ten hearts. `MobDefenseChain` commits to running
away and returns priority 70 **every tick**, so nothing else in the chain can act. The flee goal
lands thirty blocks out, the arena is a 28×28 walled field, and the drive answers:

```
primDrive NO ROUTE: at 13,-60,13 -> goal 40,-60,27 (d30.0)
```

over and over. The bot stands exactly where it is and is shot dead **five times in one run**, holding
a sword.

Running away is still the right first answer. It cannot be the only answer. If the body has not left
its block for three seconds while "fleeing", the flight is not happening, and holding priority for it
only guarantees the death it was meant to prevent. The chain now stands down for five seconds and
lets the rest of it have the tick.

```
deaths        5 -> 2
NO ROUTE      4 -> 2
min_hp      3.0 -> 5.0
```

Partial, and stated as partial: halving the deaths is not the gate.

## The bench was lying in four different ways, and that cost more than any bug

Every one of these hid a wrong conclusion before it was found.

| instrument | what it did | what it hid |
|---|---|---|
| mob fps sampling | mob courses never sampled frame rate | `mob_trio` recorded broken while the bot had **won** the fight |
| `LOAD_SENSITIVE` | matched criterion NAMES against substrings in another file | every timed pvp gate, and `mob_skeleton`'s entire red |
| the gate's name | `"the fight ran on tungsten"` | it actually means "reached striking distance" |
| `mdFleeStuck` | javadoc said "read over py4j"; it was never emitted | its own value, entirely |

**The whitelist is the shape of the rest.** The starvation guard may only mark a run INVALID when
*every* failed gate could plausibly be caused by a low frame rate, and it decided that by matching
the gate's name against keywords living somewhere else. Word a gate differently and it silently
counted as not-load-sensitive — failing closed, in the direction that blames the bot. That list was
built for nav, extended for craft, extended again for mob: three patches in one session, which is a
design fault rather than bad luck.

`Criterion` now takes `load_sensitive`, so a gate answers the question **where it is written**, while
the author still knows the answer. The keyword list stays as a fallback, so nothing moved on the day.

**What it cost before being found.** `mob_skeleton` failed five runs at 9.2–12.4 fps against a floor
of 14 — not one trustworthy — and every one was recorded as a bot failure. Those reds were then read
as a real defect, a fix was built on them, and the fix **measured worse and was reverted**. With the
instrument repaired the suite says what was true all along:

```
mob_melee     PASS
mob_trio      INVALID @ 7.0 fps
mob_skeleton  INVALID @ 9.5 fps    (was FAIL)
```

## Test results

```
craft   full suite — running, numbers go here when it lands
nav     full suite — running, numbers go here when it lands
end     full suite — running, numbers go here when it lands
pvp     flags are INERT — proved below, not sampled
```

Not filled in yet, and this does not ship until they are.

**The seven pvp gates marked `load_sensitive=True` cannot move a verdict, and that is proved rather
than hoped.** The guard's first condition is `avg_fps is not None`, and **pvp never samples frame
rate at all** — every pvp verdict carries `avg_fps = None`, checked against the most recent run. So
the guard never engages on that suite and the flags sit dormant.

Which surfaces the third instance of a hole already closed twice today: craft never sampled fps
(fixed), mob never sampled fps (fixed), **and neither does pvp**. Until it does, its starved runs are
recorded as bot failures exactly as craft's and mob's were — the flags are ready and waiting for the
number they need.

## Known

- **`mob_skeleton` cannot be judged on this hardware.** Five runs, none at or above the frame rate
  this bench considers trustworthy. That is a stand limit, not a verdict on the bot.
- **`@gamer` likewise**, at 5.0 fps against its own floor of 12 — a single-threaded render ceiling on
  a live survival world, where the same client manages 10 on the flat arena.
- **A gate named for its implementation will be misread, and then reasoned from.** `mdTung` counts
  the tungsten duelling controller, which `MobDefenseChain` hands the legs to only at striking
  distance. `mdTung=0` never meant "the engine did not run"; it meant "the bot never closed". Five
  steps of reasoning were built on the wrong reading before a counter contradicted it.
