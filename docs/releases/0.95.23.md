# 0.95.23 — the builder returns to the frame instead of drifting off (G108 natural terrain — portal lights)

Follow-up to 0.95.22. Closes the natural-terrain portal: the bot now builds AND lights the frame on
real terrain, where before the builder wandered off mid-build and never came back.

## The root: placement-recovery wander-drift

On messy natural terrain a frame (or scaffold) cell occasionally cannot reach its stand -- an
obstruction, uneven ground, a plant that regrows. `PlaceBlockTask` / `PlaceStructureBlockTask` then
fall to `TimeoutWanderTask`, and that wander DRIFTS the body far from the frame -- measured 26 blocks
away on the gamer server, holding the block, never returning -- so the build is abandoned and the
run times out.

It was isolated decisively on the gamer (survival) server:

- On a hand-laid CLEAN flat stone pad, given obsidian + cobblestone, the bot builds AND lights the
  portal -- a real `minecraft:nether_portal` block. The frame+light chain is SOUND.
- On UNEVEN natural ground it stalls; and a `pad-prep` attempt (lay the pad / clear the envelope
  before building) FAILED the same way -- laying the pad hit the identical wander-drift -- which
  proved the pad is not the root. The root is the recovery drifting the builder off the site.

The flat bench never sees this: its pad is clean, every stand is solid, no placement stalls, so the
body never drifts.

## The fix

`ConstructNetherPortalObsidianTask` now keeps the builder AT the build: while in the build phase, if
the body has strayed more than 10 blocks (horizontally) from the frame origin, it walks back to the
origin before continuing, and the drain then re-approaches the cell locally. It also pulls the body
back from the lava after a gather. It is a no-op on the flat bench, where the body stays within a
couple of blocks of the frame, so it cannot regress it.

## Validation

Natural terrain (gamer server, uneven spawn-area ground, given obsidian + cobblestone): the bot
stayed local (no drift), built the frame, and **lit the portal** -- a real `minecraft:nether_portal`
at (94,136,-35), "Done constructing nether portal." Before this fix the same build drifted off and
never completed.

## Regression

Flat obsidian flood, 5 runs: **4/5** (runs 1,2,4,5 PASS; run 3 the pre-existing intermittent
local scaffold-cell stall). The guard did NOT fire on any flat run (`Returning to the portal build`
count 0) -- the body never strays 10 blocks from the frame on a clean pad -- so it is a verified
no-op there and cannot regress the flat build. (The earlier "6/6" was one lucky batch; ~5/6 with a
residual local scaffold shimmy is the flat bench's real rate, unrelated to this change.)
