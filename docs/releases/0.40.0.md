# 0.40.0

The bot can now climb gapped/stepped terrain — running jumps between pillars, not
just adjacent steps.

## Parkour move generation (#34, #28)

`@goto` over stepped terrain used to stall: the walker's grid-BFS path source only
knew adjacent moves (walk / +1 step-up / -1 step-down). A pillar-to-pillar chain — a
+1-block step every *other* block, i.e. a +2x+1y running jump each time (course B, and
the shape of a lot of natural terrain) — had no move, so the search either handed back
a useless 2-waypoint stub or walked down to the floor and never climbed.

Added a **parkour move**: a running jump 2–4 blocks across, flat or +1 up, with the
whole flight path (feet + head) checked clear so the arc can't clip a wall. Gapped and
stepped terrain now gets a waypoint-per-landing path the walker climbs (it already
jumps toward higher waypoints). This also relieves the "Ran out of nodes" failures that
came from the search flailing at terrain it couldn't step through (#28).

Scoped tightly: parkour is only generated for **goto/follow** pathing, and only where a
plain walk isn't available in a cardinal direction — so flat-terrain branching stays
small and **combat attack/retreat pathing is byte-for-byte unchanged**.

Tests: `terrain_test` — A staircase PASS, **B steep now PASS** (reached the top,
maxY -56), D goal-snap PASS, no regression. `break_test` C_wall/D_sand/E_tool/F_api
(mining through walls) still PASS.
