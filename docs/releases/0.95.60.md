# The portal gets built

Two stalls on the way to the nether, both found from the `full59-before-portal` checkpoint.

**A submerged lava source is no longer a bucket target.** In a lake the bot could pick the
source under the surface. The bucket's ray always meets the source above it first, so the
target never came into reach, and the fallback asked the bot to stand within one block of a
lava cell, which every route refuses as lethal. It replanned beside its pool for minutes.
Only sources with no source of the same liquid above them are taken now; a lake always has
those. Lava buckets by the end of a 15-minute run from the checkpoint: 0/3 before, 2/3 after.

**A portal site that cannot be reached is dropped, not retried every tick.** Once the
approach stopped progressing, the portal task cancelled the route on every tick and started
the same approach again, so the bot stood in one cell of a shaft with the camera spinning
(traced: about 2950 ticks, the route always on step 0 or 1 of 11). The failure is now
handled once: a site with no obsidian cast yet is dropped, its lake is skipped by the next
search, and the bot moves on (baritone's blacklistClosestOnFailure, GetToBlockProcess).
Same checkpoint, five minutes: before, frozen in one cell; after, out of the shaft in 2/2.

**HOW TO TEST:**

```powershell
python deploy/runner/run_suite.py craft --only portal_lava_lake --record
python deploy/runner/gamer_smoke.py 15 --from full59-before-portal --raw-resume --record
```

Measured on the release candidate: `portal_lava_lake` PASS (portal lit at 88.9 s and 99.7 s);
two 15-minute runs from `full59-before-portal`, one PASS with no deaths, the other cast and lit
the portal at the original full59 site and entered the nether.

**Known:** that nether arrival is beside a lava sea and the bot died there trying to escape it.
That is new ground, tracked as its own item. No speed or FPS gain is claimed, and the whole
playthrough is still open.

Also since 0.95.59: `TungstenConfig.nightShelterInStorm` (default true) decides whether a daytime
thunderstorm counts as night for the no-bed shelter; measured with no winner, so the default is
unchanged. `gamer_smoke.py` gains `--tset KEY=VALUE` and `--weather KIND[:TICKS]`.
