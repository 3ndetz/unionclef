# 0.38.0

The bot can now build UP to reach a raised goal (place-as-a-move, first half: pillar).

## Pillar up to raised goals (#46, real fix for #27's tree-tops)

`@goto` used to give up on a goal it couldn't walk/jump to (a ledge, a tree top,
a tower — 0.35's unreachable give-up). Now, when the goal is clearly overhead
(≥2 blocks up, nearly directly above) and the bot has a block, it **pillars up** —
places blocks under itself and jumps, adjacent to the target, then steps onto it —
instead of abandoning.

- `PillarTask` — the vertical place-under-self + jump execution primitive (like the
  godbridge, but up). Also exposed via py4j `pillarTo(y)`.
- `equipBuildBlock` auto-equips a cheap block (cobblestone/dirt/stone/…) from the
  inventory; the agent's own block in hand also counts.
- Tightened trigger (goal ≥2 up, within 1.5 horizontally, 14s no progress) so it only
  fires on a genuine vertical reach — normal walking/staircase nav is untouched.

Tests: `pillar_test` (rises ~5 blocks, no crash), `pillar_reach_test` (`@goto` a
10-high pillar top → pillars up + reaches, 37s), terrain staircase A still reaches
(no regression).
