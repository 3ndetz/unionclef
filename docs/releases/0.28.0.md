# 0.28.0

Combat release. The PVP bot stops throwing itself into the void and actually
lands its hits. On a bedwars-style void island it now fights a full match
without a single self-inflicted fall. Tested on the docker autotest stand
(`deploy/runner/bedwars_combat_test.py`).

## The bot no longer walks/jumps off the island in a fight

The old "bunch of safety systems" didn't work because the falls came from the
safety systems themselves. In-combat telemetry pinned it down: the stage machine
was the culprit — `DANGER_BATTLE` repositioning **sprinted** and the
`DANGER_IMMINENT` brake **jumped**, and next to a small island's rim that
brake-jump launched the bot straight off. The reactive edge-check only looked
1.35 blocks ahead, which sprint momentum (~0.28/tick) simply overshot.

Now void-safety is the final word on movement in every combat frame:

- **No sprint near a rim, no jump toward a drop.** A brake or reposition can no
  longer sprint-overshoot or launch the bot off the edge.
- **Vanilla sneak edge-stop.** When the bot's heading (keys *or* momentum) points
  at a drop, it plants with sneak — Minecraft won't let a sneaking player walk off
  a ledge — using a speed-scaled lookahead so a sprinter stops in time.
- **Knockback recovery preserved.** If only momentum (not the bot's own input)
  points at the void — i.e. it got knocked — the toward-island brake input is kept
  and sneak is *added*, instead of stranding it sliding at the rim.
- **No chasing an enemy into the void.** After knocking someone off, the bot holds
  position instead of following them over the edge (and stops the `Ran out of
  nodes` spam from pathing at a target that's falling).

Result on a 5×5 void-island bridge arena, bot vs a stationary target, 90 s:
**11 kills, 0 deaths, 0 falls** (min Y never left the island). Before: 2–5 falls
per minute. In a mutual fight (both bots hunting each other) it now trades
knockback-falls symmetrically with an identical opponent — that's ordinary PvP,
not the old walk-into-the-void.

## Faster aim

The bot "turned slowly" and its crosshair lagged a strafing or knocked-back
target — the trigger gate logged a 90° angle while the weapon was off cooldown,
so swings never connected. WindMouse combat tuning bumped for snappier tracking
(`gravity` 2.0→3.2, `maxStep` 4.0→7.0, snap threshold 0.5→0.4). This is a combat
aura, not a legit-look aimer, so effectiveness wins over human-like slowness.

## How to test

```
;punk <player>          # hunt one player (approach A* + combat)
```
or via py4j / MCP: `punk("name")`, `punkAny(allow, avoid)`, `punkStop()`.

Repro/regression: `deploy/runner/bedwars_combat_test.py [secs] [solo|mutual] [flat|bridge]`
builds a void island (flat 13×13, or two 5×5 islands + a 1-wide bridge), punks,
and reports kills/deaths/falls from the scoreboard. `solo bridge` is the
self-inflicted-fall test; success = ≥1 kill and 0 falls.
