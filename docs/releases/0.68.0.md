## Smelting works again — and it had never worked on 1.21.11

The headline is one line of leftover port scaffolding:

```java
//$$ fuelTimeMap = new java.util.HashMap<>(); // TODO [1.21.11] createFuelTimeMap() removed
```

An empty fuel map does not tell its callers "we don't know yet". It tells them **nothing in the
game burns**. `isFuel(coal)` was false, `getFuelAmount(coal)` was zero, and so the bot's count of
fuel in its own pack was zero no matter what it carried. All three smelting devices — furnace,
blast furnace and smoker — read that number, so all three were dead, and with them the gate to iron
and everything past stone.

From the outside it looked like this, with **eight coal in the pack** and a furnace already placed
and open:

```
<Doing stuff in [furnace] container> Getting Fuel
  -> <Collect Fuel: x2.0> Collecting coal.
    -> <Mine And Collect: [[coal]]>
      -> <Wander for Infinity blocks> Exploring.
```

It walked off to mine coal it was already holding, and it could never have stopped — zero does not
rise no matter how much coal you add.

1.21.11 did not delete the data, it moved it: fuels are now a registry on the world. So the fix
asks the game rather than hardcoding a table, which means datapack and modded fuels are right by
construction too.

## Crafting: the loop could not see the stack in its own cursor

Filling a grid slot takes two ticks — the mover picks the ingredient **up** into the cursor, then
puts it **down** next tick. In between it is in neither the pack nor the grid, and the loop's "have
we run out?" question deliberately does not look at the cursor. So whenever the stack in flight was
the last of its kind, the craft decided it had run out, dropped the mover mid-move, and the tail of
the same method put the ingredient back in the pack. Next tick, same thing. Forever.

```
90x CURSORBACK manualTail holding=minecraft:oak_log
30x CURSORBACK manualTail holding=minecraft:stick
30x CURSORBACK manualTail holding=minecraft:oak_planks
```

## Mid-mining tool swap, ported without a version fork

`makeSureToolIsEquipped` had its entire body switched off on 1.21.11, so a better pickaxe picked up
into the cursor was never moved into the hand. It now compares what the two tools actually do to
the block in front of the bot rather than what class they are, which needs no version branch at all
and also fixes a flaw present on every version: the old code equipped any mining tool over a
non-mining one even when that was a downgrade.

Honest limit: this is correct by reading and regresses nothing, but the swap was not observed
firing in these courses (`toolSwap=0`), so its benefit is not yet demonstrated.

## How to test it yourself

```
@get iron_ingot
```

with logs, cobblestone, raw iron and coal in the pack. The bot should craft a table, craft a
furnace, place it, load fuel and ore, and take the ingot out. Before this release it built no
furnace at all.

```
@get crafting_table
@get stone_pickaxe
@get cobblestone 8
```

are the rungs below it, and all four run on a flat world in a couple of minutes each.
