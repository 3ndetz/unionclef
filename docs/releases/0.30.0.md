# 0.30.0

Navigation release: the bot stops stalling on terrain. `@gamer`/`@goto`/`@get`
now cross real hills and mountains instead of grinding to a halt partway.

## Why the bot got stuck on terrain

Under tungsten-primary, altoclef navigation ran the physics executor — it replays
a *simulated* trajectory. On steps and slopes that sim DRIFTS from where the bot
actually is; once the drift passes a threshold the executor hard-stops, and the
search then rejects its own freshly-computed path ("root far from player"). The
pathfinder ends up perpetually busy, never yielding, and the bot crawls or freezes.
On the survival stand the bot would take one log and then stall on the mountain.

## The fix — drift-immune terrain walking

Terrain movement now follows a **block path with the BlockPathWalker**, which
sprints from the bot's REAL position toward each waypoint (jumping up steps). It
reads where the bot actually is every tick, so drift can't accumulate — it always
corrects from the ground truth. Path source, cheapest first:

1. a fast grid BFS for clean / nearby terrain, else
2. the **elevation-aware block path the tungsten block-space search already
   computes** — the robust, any-terrain route (no baritone involved; it's all
   tungsten).

The physics executor is kept only for the final ~4-block precise approach and for
water / slime / parkour. The walker force-stops the drifting pathfinder so it can
no longer trap the bot.

Result:
- 12-step staircase (`@goto`): reaches the top drift-free (previously drift-aborted).
- Real survival mountain (gamer-server): the bot crossed ~40 blocks of natural
  terrain, descended a hill, found a spruce tree and chopped it — full health, no
  falls — where it used to stall immediately.
- `swap_test` still PASS (no flat-nav regression).

## Known / in progress

- **Parkour isn't covered yet**: jump-gaps and 2-block-wall climbs still fall back
  to the physics executor, which struggles there. Normal walking/climbing terrain
  is the fix; parkour is the next step.
- Sustained multi-tree gathering over long runs needs more soak time (one
  end-of-run stall seen).
- Combat void-safety (v0.28.0/v0.29.0) and `runAwayPlayer` (v0.29.0) unchanged.
