# 0.95.7 — a wedged builder no longer freezes the bot at a block

A patch on 0.95.6, from a day-locked run after iron: the bot froze for 200 seconds at one
spot trying to mine a block 1.4 blocks away, "Waiting for the approach to finish placing."

---

## The fix (G105)

To reach a block to mine, `DestroyBlockTask` lets the approach build its own footing — a
bridge, a pillar, a place — and while that builder owns the inputs it both resets the
stall checkers and yields the whole task to it. It did so **unconditionally, every tick**.
A builder that is actually working moves the body (a pillar rises, a bridge steps forward);
one that **cycles without advancing** — plan a pillar, it fails, re-plan the same, repeat —
moves nothing, and the unconditional shield then suppressed the give-up machinery forever.
Measured at the freeze: the builder-yield ran into the thousands while the body never moved.

Now a **break** stays shielded unconditionally (a dig-down is still by design, and the
executor's own break timeout bounds a stuck break), but a **place/pillar/bridge** is
shielded only while it is moving the body. Once it has held the body still past a generous
cap (`BUILD_HELD_MAX`, 10 s), the shield drops and the existing give-up condemns the target
and reroutes. A healthy build — which advances or rises within a few ticks — never reaches
the cap, so normal bridging, pillaring and digging are untouched.

**HOW TO TEST:** the counter `dbBuildHeldStuck` (in `placeStats`) reads 0 in a healthy run
and non-zero only when the watchdog has fired. Nav suite (nav_break, nav_bridge, nav_wall2
all exercise the build-yield) stays green; a day-locked survival run no longer freezes at a
mining target.

## Note

The freeze is an in-memory transient (a place/pillar re-plan cycle), not reproducible from a
world checkpoint — restoring the exact freeze position ran fine. So this is a defensive core
bound on how long a non-advancing builder may suppress stall detection, verified by
no-regression (nav suite) and by the day-locked run no longer freezing, rather than by a
deterministic repro.
