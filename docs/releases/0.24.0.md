# 0.24.0

## Features

- **Tungsten uses slime blocks for parkour.** `;goto` now plans and executes
  bounce routes: sprint off a ledge, fall onto slime (no fall damage), ride the
  bounce up to platforms a jump can't reach. Verified by autotest: fall-4 →
  bounce → +3 platform and fall-3 → bounce → +2 platform, both in ~6s at full
  health. Under the hood: fall-height pruning exempts slime-bottomed columns,
  block-space generates bounce-height children from cumulative descent, and
  `SlimeBounceMove` no longer presses jump on the landing tick (jump() used to
  replace the bounce velocity with an ordinary 0.42 hop).
  Physics note: a jump in place on slime peaks at ~1.9 blocks — every bounce
  route needs a drop-in. Details: `docs/features/TUNGSTEN_SURFACES.md`.

- **Autotest stand, phase 0 of `docs/AUTOTESTING.md`.** `deploy/` now has a
  self-contained docker stand (vanilla 1.21.11 server + headless client on the
  mineswarm image) and a slime parkour test runner. `sh deploy/autotest.sh` on
  the docker host = build → deploy jar → restart client → run courses → report.

## Fixes

- **`;goto` was silently ignored after `;stop`.** StopCommand set
  `PATHFINDER.stop` and nothing ever reset it — GotoCommand bailed on the stale
  flag before reaching the code that clears it. A fresh `;goto` now overrides
  the old stop.
- **Physics search could hand the executor a path starting far from the
  player** (instant "drift 8.9 blocks" abort). `shouldResetSearch` re-rooted
  the search while the emission of the walked prefix sat in a callback that
  never fired when the executor was idle. The prefix is now emitted inline.

## How to test

Build a course: start platform, slime pad 4 blocks below, target platform +3
above the slime a couple of blocks to the side (exact geometry in
`deploy/runner/slime_test.py`, `COURSE_CMDS`). Then `;goto <x> <y> <z>` onto
the target platform. Or run the whole thing: `sh deploy/autotest.sh` on a
machine with docker + the mineswarm-mc image.

## Known limitations

- Block-space heuristic penalizes descending, so deep slime pits may need the
  slow fallback search pass.
- Structures near a course confuse routing — test worlds are generated with
  `GENERATE_STRUCTURES=false`.
