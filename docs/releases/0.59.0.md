# 0.59.0 — visualisation back on, sharper combat camera, path from a ledge, no more bow-punching

Everything here came out of a live review of recorded PvP test clips. Several of these are
long-standing bugs that only became visible once the runs were filmed.

## Fixes

- **Path from a BLOCK EDGE over a void.** `BlockSpacePathFinder` started the search at
  `player.getBlockPos()`, which floors the entity *centre* — standing on the lip of a block
  above a drop floors into the neighbouring column, whose floor is air, so the start node
  looked airborne, generated no children and the search died with "Ran out of nodes" while the
  bot stood on solid ground doing nothing. The start now snaps to the cell that actually
  supports the player (collision-box footprint → landing cell → small sweep).
- **Stuck-fix no longer fires when nothing is stuck.** `UnstuckChain` treated "moved < 1.5
  blocks in ~10s" as stuck with no check that the bot was even trying to move, and only stood
  down for tungsten-*primary*. Combat (circle-strafing holds position on purpose), any
  non-primary tungsten segment, crafting and waiting all tripped it, and the shimmy threw the
  aim/task away. Now guarded on: in combat, tungsten active, or no movement key pressed.
- **Combat swings a WEAPON.** The punk pipeline swung whatever was in hand — after a bow shot
  the bot kept "fighting" with the bow while a sword sat in the hotbar. New `WeaponSelector`
  picks the best hotbar melee weapon during the combat stage.
- **Config persistence no longer shadows shipped defaults.** `tungsten.json` is rewritten whole
  on every `;settings x y`, so any value saved once outlived every future default — stands were
  silently running months-old combat tuning with *all* visualisation off. New `;settings reset`
  and py4j `resetTungstenConfig()`.

## Visualisation

- **Arrow trajectory rendering**: the bow now draws its simulated flight arc (vanilla drag +
  gravity) and a marker on the predicted impact point, re-aimed every tick while drawing.
- Path / jump-arc / combat-node / break / place overlays confirmed rendering again on the stand
  (they were only invisible because of the persisted config above).

## Combat feel

- Camera tuned for a real flick instead of a glide: WindMouse gravity 5.5 → 12, maxStep 10 → 25
  deg/frame, wind 0.35 → 0.15. Still entirely through the mouse pipeline (no setYaw/setPitch).
- Bow aim uses the fast turn mode — shots no longer spend seconds converging.

## New levers

- `resetTungstenConfig()` — whole config back to shipped defaults (py4j + `;settings reset`).
- `respawnPlayer()` — close the death screen and respawn. A dead bot used to lie there for the
  whole run with autoRespawn not firing.

## Test suite (`deploy/runner/run_suite.py`)

- Every combat scenario now has a **death gate** (`kills >= deaths` in mutual duels, `deaths ==
  0` against a fleeing/handicapped opponent). The old criteria reported a 1-kill/4-death run as
  PASS.
- `chase_terrain` moved to the **real world generator** (`gamer-server`, normal terrain): the
  victim runs on baritone, our bot must catch and kill it. Honest current result: **FAIL** — the
  chaser mines into a hillside, stalls and the runner escapes. Move-generation/reachability pass
  still outstanding.
- Visualisation forced on and config reset before every recorded run; per-player spawnpoint;
  clips recorded per scenario (fragmented mp4 + bitrate cap).

## Known broken (do not claim otherwise)

- Real-terrain chase (above).
- Bow-flee / kite: no primitive exists; the flee executor owns the camera.
- Edge duel: the bot still walks off a 5×5 platform under knockback pressure.
