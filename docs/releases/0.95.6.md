# 0.95.6 — a craft crafts, it doesn't dig across the world for a dropped copy

A patch on 0.95.5, from the third 60-minute run: the bot opened by spending its first
seven minutes digging ten blocks straight down for a `wooden_pickaxe` a previous life had
dropped, while the spruce to craft one stood across the lake.

---

## The fix (G93)

`CraftInTableTask` inherited `ResourceTask`'s pickup-before-craft with the default
`getPickupRange()` of `-1` (unlimited). `ResourceTask.onTick` returns a
`PickupDroppedItemTask` for **any** drop of the craft target while the range is negative,
with no cost check — so a copy buried ten blocks down outranked crafting one from planks in
hand. Its sibling `CraftInInventoryTask` already overrides the range to `0` ("this shouldnt
pickup items"); the table craft simply never got the same override.

Added it. A table craft now gathers or uses its materials and makes the item; it no longer
detours to scavenge a distant or buried copy. Ordinary pickup paths still collect a drop
when a pickup is the actual goal — this only stops a **craft** from turning into a dig.

**HOW TO TEST:** `python deploy/runner/buried_drop_vs_craft_test.py` — two logs and two
sticks in the pack (enough to craft a wooden pickaxe), a `wooden_pickaxe` item dropped in a
sealed pocket eight blocks straight down, then `@get wooden_pickaxe 1`. On this build the
bot crafts the pickaxe in 7.9s and never descends (min Y stays at the surface, -60 against a
floor top of -61). Before the fix it dug down for the drop.

## Regression

- Full nav suite 14/14 PASS (0 gate failures, 0 invalid) on this build.
- The G100 air-pocket bench still PASS (dig=2, surfaced) — drown-escape unaffected.
