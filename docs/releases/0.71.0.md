## The bot gets out of water and lava again — and picks water over dry land

Two survival reflexes had the same defect, and neither announced it.

`GetOutOfWaterTask` and `EscapeFromLavaTask` both expressed their goal as a **predicate**: "not
water and not next to water", "not lava and not next to lava". Baritone could consume that directly,
because it *searched* — a predicate is a perfectly good goal function for A*, which visits candidate
cells and asks each one. The tungsten drive does not search; it **steers at a point**. A goal with no
point in it cannot be translated, so the task ran and the body did not move.

Both now use one new shape, `AltoGoal.NearestSatisfying`, which expands outward from the player to
the first cell where the test passes and hands *that* back as the target. The search lives in one
place with the decisions made once: nearest-first expansion, vertical offsets last (walking beats
climbing), a radius cap, and one scan per tick — `target()` is read every tick, and rescanning a
shell sixty times a second is how a goal type becomes a frame-rate problem.

**Lava is two-stage, and the order is the behaviour.** The old heuristic priced water at −100:
escaping *into* water is strongly preferred because it puts the fire out, and that preference does
not fall off with distance. A predicate cannot carry a preference — the order of calls can. So it
looks for water first and settles for dry ground only if none is near.

```
nav_water     PASS   avg_fps 16.2   self_falls 0   freezes 0
escape_lava   PASS   surv=145/145   lavaCond=101/145   lavaEsc=101
                     bot exits to WATER six blocks south, not dry ground one step east
```

## Test results

Craft ladder, twelve courses: **9 PASS, 0 gate failures, 3 INVALID** (host at 9.9–10.0 fps, correctly
classified as the machine rather than counted as breakage). Nav suite 11/11 on the same code.

## Known, and worth reading before trusting a new course

`escape_lava` took seven runs to become an instrument, and produced along the way a false red (its
own arena), a false green (the spawn point satisfied its exit condition), and one **fully
corroborated wrong finding** — three independent witnesses agreeing that lava escape was dead while
the task runner was simply switched off, because the course issued no command.

That last one is now RULE TWO in the checklist: `TaskRunner.tick()` opens with `if (!active)
return;`, so an idle bot ticks **no** chains at all. Agreement between witnesses is not truth when
they share a hidden assumption.
