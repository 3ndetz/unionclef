# 0.53.0 — tungsten-primary climbs terrain (smartMoves coupled)

Step toward the "fully migrate to tungsten" goal.

## What's new

`setTungstenPathing(true)` now also enables **smartMoves**. tungsten-primary needs the
SmartMoves neighbour generation (parkour / jump-up moves in the async block-space search)
to climb terrain; without it, `@goto`/`@get`/`@gamer` under tungsten-primary followed a
grid-BFS stub that couldn't route staircases or steep climbs.

With them coupled, the terrain stand suite via `@goto`+primary passes the reachable
courses: A (staircase) PASS, B (steep) PASS, D (invalid-goal snap) PASS. (C, a 2-block
wall, is only reachable with a block in hand — correct.)

## Status of the full migration (not yet the default)

tungsten-primary is **still not the default** (`setTungstenPathing(true)` to opt in).
A bounded `@gamer`-on-tungsten smoke shows the bot stays responsive and moves, but on the
gamer-server's harder terrain the block-space search still hits "Ran out of nodes" and the
physics leg drifts, so it stalls without making item progress. The remaining blocker for
the default flip is that pathfinder node-budget / hard-terrain issue — a dedicated pass.

Already validated on tungsten this line: follow a moving target (v0.52), melee + ranged
combat vs a moving target, terrain A/B/D, water. The stack works for bounded scenarios;
full-survival-default awaits the node-budget fix.

## How to test

`WDBG=1 python3 deploy/runner/terrain_test.py` (courses A/B/C/D via @goto+primary+smartMoves,
with per-tick walker/primDrive decision logs). `gamer_smoke.py` for the bounded survival run.
