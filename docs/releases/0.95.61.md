# The old frame gets finished

The portal task keeps its site in memory only. After any interruption -- a night shelter, a
food run, a death -- a fresh copy of the task searched from scratch, and at the original full59
site the region search landed one block below the frame the previous copy had cast. That old
obsidian then sat in the new frame's way: it blocked the line from the lava stand to the cell
being cast, so the bot stepped off the stand to get a better view, stepped back, and repeated.
The first long playthrough stood at that site for 39 minutes.

Before choosing a new site the task now looks for a frame already partly cast, around the bot
and around the site it is about to choose. Every obsidian block nearby is tried in every frame
slot; the origin with the most cells already cast (at least two, opening clear) wins, and the
chat says "Resuming the portal frame already cast at ...".

Same checkpoint (`cp1015-1535-t605`, the full59 site): before, 0/3 runs got past the cast;
after, 2/2 finished the old frame, lit it and entered the nether.

**HOW TO TEST:**

```powershell
python deploy/runner/gamer_smoke.py 8 --from cp1015-1535-t605 --raw-resume --record
python deploy/runner/run_suite.py craft --only portal_lava_lake --record
```

`portal_lava_lake` still passes (portal lit at 97.6 s, no deaths).

**Known:** the nether is new ground for the playthrough. One of the two runs that got there was
later shot by a piglin (no gold armour yet); an earlier run died in a lava sea on arrival. Both
are tracked. No speed or FPS gain is claimed.
