# Navigation stops release their block work

Explicit navigation cancellation now abandons the executor's queued mining or
placement job, clears its continuation callback and releases the inputs and aim
owned by that job. The replay drift behavior is unchanged. Inactive bridge,
pillar and swim-out tasks no longer clear an unrelated fresh aiming target.
`cancelledBlockWork` in the executor diagnostic counts abandoned block jobs,
not stop calls or placed blocks.

**HOW TO TEST:** on a supported dry floor, equip a stone pickaxe and start a
reachable obsidian dig through Py4J `mineBlocks`. While it is mining, call
`stopPathing()` or send `;stop` using the configured Tungsten command prefix.
The swing and mining outline must stop while the obsidian remains intact.
Repeated cancellation with no job must not add to `cancelledBlockWork`.
An independently requested fresh aim must survive an otherwise inactive
navigation stop; normal aim expiration still applies.

The exact isolated candidate passed six explicit mining cancellations
(three central, three helper), a separate three-arm fresh-aim fixture and
42 adjacent courses: six each of table crafting, flat ground, stairs,
descent, breaking, bridging and gaps. These original recordings were reviewed.
Six fresh lava tasks from the same original saved entry also passed their
independent functional, health, trace, runtime and conservation audits at
29.5-30 FPS and health20; their film review is still pending. These results
do not establish a historical speed difference or the cause of full59.

**HOW TO TEST adjacent behavior:**

# Accumulated changes since 0.95.56

- Near goals route to any safe cell within their actual radius rather than
  requiring the original point to be standable. `nearGoalSearchesRegion` is ON.
  **HOW TO TEST:** resume a saved approach where the point lies in an obstacle
  but a reachable cell is inside the radius. Run the ordinary task; it should
  approach a valid cell and finish its Near child without changing the radius.
- The fixed fall-cost calculation can reuse its bit-identical cached value.
  `cacheFixedFallHeuristic` is ON. **HOW TO TEST:** compare the same saved
  approach with `@set cacheFixedFallHeuristic true` and `false`. Costs and
  arrival behavior must agree. No FPS gain is claimed.
- Each planner request owns its available-block budget. Parallel requests
  cannot change another search's construction allowance.
  **HOW TO TEST:** request routes for players with different block stocks;
  each route's placements must fit its captured stock.
- Liquid edges retain their live validation, and a swimming movement must
  enter its destination before reporting success.
  **HOW TO TEST:** run `nav_water` and watch a saved vertical water approach;
  an already-matching height alone must not finish the wrong cell.
- Scanner completions are applied on the client thread and obsolete-world
  completions are discarded. Queued menu reconnects are cancelled before
  survival teardown and checkpoint restoration.
  **HOW TO TEST:** disconnect during scanning, restore an existing checkpoint
  while offline and reconnect explicitly. Old-world results must not be
  accepted, and the saved player must stay unchanged before reconnect.
- Bench verdicts reject survival failures even if a later progress rung appears;
  recording and runtime-log windows retain their actual run boundaries.
  **HOW TO TEST:** `python deploy/runner/test_process.py`, then the saved-entry
  gamer command above. Inspect the death verdict and the completed recording.
