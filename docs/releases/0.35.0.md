# 0.35.0

Navigation no longer spins forever on an unreachable goal (#27).

## Unreachable-goal give-up (#27)

`@goto` / agent goals that can't be reached under the current move set (e.g. the
top of a tree or a tall pillar — the pathfinder can't place/pillar yet) used to
make the pathfinder **search forever**: the anti-stuck timer reset on any raw
movement, so a bot wandering in place near the goal never gave up, and
`driveTungstenPrimary` reset the parent task's progress checker every tick so the
task never failed.

Now it tracks **net progress toward the goal** (best distance reached). If that
doesn't improve for 14 seconds (and we're still >2 blocks away), it stops the
tungsten pathing and yields **without** resetting the progress checker, so the task
fails cleanly instead of looping. Low-risk: a temporary plateau (a long detour
around an obstacle) just yields briefly and re-measures on re-entry.

Test (`deploy/runner/unreachable_test.py`): `@goto` the top of a 10-high pillar →
gives up at ~21s (walk to base + 14s no-progress), does **not** reach, **no crash**.
Regression: the reachable staircase course still reaches the top (no false give-up).

## Note

This is the short-term fix — a clean give-up on impossible goals. The real fix so
the bot can actually *reach* such goals (pillar up / bridge across) is
place-as-a-move in the pathfinder, tracked as #27's root cause and an elevated
priority (the bot currently only ever places blocks via explicit primitives, never
during `@goto`).
