# 0.67.0 — tungsten is the pathfinder the mod ships with

## The headline

`TungstenHelper.primary` shipped **false**. Out of the box every altoclef goal went to shredder,
and tungsten drove only after a harness or an agent called `setTungstenPathing(true)`. So the
configuration under test was never the configuration shipped — and the moment the bench was pointed
at the shipped one, the bot turned out to stand still.

It does not any more. `@gamer` on shipped defaults: **wood at 21.3s, GAMER_SMOKE PASS**, nobody
flipping a switch first. `pdLegacy=0` on every run — the legacy engine was never handed the goal.

## Two movement bugs, both found in the log

**The route was rooted one cell below the feet.** `getBlockPos()` is a plain floor of y, and a
player standing on solid ground sits at y = 132.99999… about as often as at exactly 133. The first
edge came out an ASCEND from the buried cell, `MovementAscend` waited to be standing at a source the
player never occupies, and it held forward against the block face until the queue timed out and
planned the same thing again. The route is now rooted at `playerFeet` — the convention every ported
movement tests itself against.

**The queue was given running jumps it has no movement for.** Routes come from CombatPathfinder with
parkour on, so they contain edges like `{90,134,-36}->{86,135,-34}` — four blocks across and one up.
With no `MovementParkour`, that shape fell through to a dumb steer which walked at the gap and gave
up a second and a half later. The queue now truncates at the first shape it cannot execute, and a
route whose FIRST edge is a jump is refused outright — which sends it to the walker, the thing that
sprint-jumps toward a waypoint and can clear the gap.

Measured across four runs of the same five-minute window: positions 3 → 8 → 12, `mqSteps` 0 → 445,
`pdStallReset` 51 → 0.

## smartMoves stays off, and now for a measured reason

Turning it on shipped-wide failed `nav_water` **3 runs out of 3**, each ending at exactly
`final_dist=25.5` with 11-12 client freezes. `SmartMoves.generate` emits walk, jump-up, descend and
parkour and nothing else, so replacing the blind neighbour scan with it removes swimming outright.
It remains an agent lever until it covers what the blind scan covers.

## Getting baritone out (G-0)

- **`AltoGoal`** — altoclef's own goal type. A goal answers two questions, WHERE and ARE WE THERE,
  and neither needs a pathfinder. The drive accepts both vocabularies, so tasks move over one at a
  time and the tree compiles at every step. Four leaf tasks moved.
- **`Nav`** — one facade for the engine. About sixty calls in thirty files said one of four things
  (stop, are we pathing, is it safe to interrupt, is there a goal); 107 call sites now say it to
  `Nav`. When the legacy engine goes, it goes from one file.
- **`BaritoneHelper.calculateGenericHeuristic`** — 27 callers, and it was importing a pathfinder to
  do arithmetic. Ported with the numbers unchanged.

## Bench

`nav` 11/12 (nav_slime's single freeze is host noise — it passes 3/3 in isolation), `mob_melee`
PASS, `@gamer` PASS on shipped defaults.

## How to test

- Nothing to switch on: `;goto x y z` and `@gamer` already run on tungsten.
- `@gamer` on a fresh survival world — it should reach wood within the first minute.
- If you want the old pairing for comparison, `setTungstenPathing(true)` still turns on smartMoves
  and the two shredder-side flags together.
