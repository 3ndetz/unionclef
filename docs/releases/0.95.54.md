# 0.95.54 — placement ownership, task handoffs and replay landings

Casting deaths and the original full59 stall remain open. Completed tests below
have separate denominators; passing the retained portal course is not universal safety.

The bucket portal could leave a walking route running while it tried to place its upper
cobblestone mould. The bot kept jumping against the wall and the placement never finished.
The builder now releases its navigator waypoint walk when it takes control to place or
pillar, and when its queue is cleared. A follow walk that replaced that route is retained.

Task replacement now respects a protected child through every wrapper. Previously a
plain parent could bypass a child's airborne or inventory-cursor guard. A child retained
by its guard keeps ticking until it can yield; explicit user stop and chain interruption
remain unconditional. The task-list read API snapshots on the client thread, fixing an
observer null dereference during a portal replay. Optional bounded movement tracing
records task changes and the movement drivers without changing movement decisions.

Physics plans can outlive the state they were calculated from. A recorded gap failure
started with stale horizontal velocity and missed the destination's lip. Before replaying
a fresh grounded trajectory, the executor now simulates its inputs from the actual body,
including mouse quantization. If a planned landing is missed, it releases the approach
and notifies the caller so it can replan. It cancels only while the body still has real
collision support; water, ladders, airborne motion and owned aim are excluded. The
1.21.11 player simulation also matches vanilla's horizontal vector velocity deadzone,
which previously erased a small strafe component while the other axis was moving.

## How to test

At a lava lake, carry water and an empty bucket, an iron pickaxe, flint and steel, and
cobblestone. Run `@test portalbucket`. It should cast and light the frame without a diamond
pickaxe. The upper mould should finish rather than repeatedly jumping against its wall.

```
python deploy/runner/run_suite.py craft --only portal_lava_lake --repeat 6 --record
python deploy/runner/run_suite.py nav --only nav_flat,nav_staircase,nav_descend,nav_break,nav_wall2,nav_bridge --repeat 3 --record
python deploy/runner/run_suite.py nav --only nav_gaps,nav_steep,nav_water,nav_ladder,nav_slime --repeat 6 --record
python deploy/runner/run_suite.py pvp --only chase_flat --repeat 3 --record
python deploy/runner/diag_build.py
python deploy/runner/task_force_contract.py
python deploy/runner/task_force_contract.py --jar versions/1.21.11/build/libs/unionclef-1.21.11-0.95.54.jar
```

For the task guard, craft with a full inventory and an item on the cursor; the protected
child should finish returning the item before its wrapper replaces it. `@stop` must still
cancel immediately. Over py4j, `getTaskInterruptionStats()` exposes cumulative vetoes;
`setMovementTrace(true)` starts bounded capture, `getMovementTrace(sequence)` drains
rows, and `setMovementTrace(false)` disables recording. Tracing ships off.

For replay landings, run `;goto X Y Z` across a jump that needs physics. A refused
stale plan should be followed by a new approach and actual arrival. `execState()`
reports `liveLanding=checks/unsafe/refused` and `liveLandingMaxNs`. The checks and
unsafe observations are counted with `replayChecksLiveLandings` either on or off;
the flag gates refusal only and ships on. It does not gate the vanilla vector repair.
