# 0.61.0 — cleanup: the fast route now guides the physics search, the reactive layer is gone

This release deletes work rather than adding it. An audit of everything since v0.58.0 found that the
actual task — *route with a fast block planner, execute that route with tungsten physics* — was
never wired, and that seven commits of situational patching had grown around the gap.
Full write-up: `docs/ai/postmortem-2026-07-27-fast-pathing.md`.

## Wired (the missing line)

- `PathFinder.findBlockPath` now returns the **`FastPlanner`** route, so the physics search is guided
  by it (`NEXT_CLOSEST_BLOCKNODE_IDX` / `computeHeuristic` already consumed a block path). One guided
  engine instead of two racing ones.
- **Completeness guard**: the fast route is used only when it reaches the goal. `FastPlanner` models
  walking, climbing, dropping and gap jumps but not slime bounces, ladders, vines or swimming;
  guiding the physics engine with a partial route through such terrain hid those moves and broke the
  slime drop-bounce course. Proven with the toggle (OFF passed, ON failed) and fixed.

## Deleted (situational compensation, ~200 lines)

- `FastPlanner.blockCell` / `blockArea` / the BLOCKED map — a 30 s cell blacklist that could ban the
  bot's own escape routes.
- `FastPlanner.planEscape` + the `MAX_FALL_OVERRIDE` ThreadLocal (deep-fall "perch escape").
- All three jam watchdogs (two in `FollowEntityTask`, one in `PunkPlayerTask`) with their anchors,
  counters and magic thresholds.
- The cooldown-gated "local climb physics leg", which also swallowed the long-range re-plan because
  `PathFinder.find` early-returns while a search is active.
- The walker's second navigation of the fast route in `FollowEntityTask`.

## Kept (core work, unchanged)

`PlayerFit` real-collision passability; the perf set (fast block classification, `MIN_PRIORITY`
search threads, 1 ms yield per 256 expansions, producer-side render gating); `snapToSupport`; the
drift abort no longer killing the search; bow lead from position deltas; `WeaponSelector`;
`getPerfStats` / `resetTungstenConfig` / `respawnPlayer`; the `uctest` suite.

## Regressions run after the cleanup

`slime_test` A_drop_bounce + B_short_bounce PASS (twice), `slab_hole` PASS, `melee_basic` PASS,
`narrow_bridge_duel` PASS, `chase_flat` PASS.

## Still red

`chase_terrain` on the real world generator: the bot travels and climbs but does not catch the
runner. The remaining problem is the execution contract (walker bails on `no LOS`, jumps without
forward carry, competes with the executor for movement keys), not the route.
