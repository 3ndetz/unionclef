# 0.46.0

Combat rework, pillar 1 of N: **the bot now moves toward a moving target** instead of
standing still. Aim-shake and always-moving are still to come — treat this as a step, not
"combat fixed".

## Movement / approach (LIVE-A)

The #1 live failure was: on a moving target the bot re-planned forever and **stood still**,
and it never approached when close — so it never got in reach and never attacked. Root: the
immediate mover was **off by default** (`followBlockPathFinderEnabled`), so follow/punk
leaned only on the physics pathfinder, which re-plans every time the target strays and never
emits a path against a moving target.

Fixes:
- The immediate BFS walker is **on by default** — it sprints from the real position toward
  the target every tick (drift-immune), so the bot chases a moving target immediately while
  the physics A* computes.
- Its DIRECT chase mode had the same **spin** bug fixed for `;goto` in 0.44.0 (only the BFS
  mode was fixed then): pressing forward before the humanized aim converged made it circle
  the target. It now turns to face first, then moves (keeping air momentum for jumps).

Stand result (`pvp_moving_test`): the bot chases a running victim and lands hits (18 dmg,
first hit 15.5s, 0 freeze windows); `terrain` nav 8/8 (no regression).

**Note:** if you have a saved `tungsten.json`, it overrides the new default — delete it (or
set `followBlockPathFinderEnabled: true`) to get the fix.
