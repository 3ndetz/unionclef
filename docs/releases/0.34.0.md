# 0.34.0

Combat is dynamic now, and a client crash on mining-goto is fixed.

## Dynamic combat movement (was static — stand and hit)

The PvP bot rooted in place: `CombatController.tick` only aimed (WindMouse) and
auto-clicked (triggerBot) — there was **zero leg movement**. So it just rotated to
the target and hit, never strafed, kited, or jumped (it even rendered jump
trajectories it never executed).

Added `CombatController.combatMove()`:

- **Line of sight + safe** → **circle-strafe** around the target (randomised
  direction flips), **kite to melee reach** (close in when far, back off when too
  close), and **crit-jumps** on a randomised cadence.
- **No line of sight** (target occluded by a wall or another entity) → **walk the
  pathfinder route** to flank the occluder instead of spinning in place.
- **Danger** (safety braking / repositioning near a drop) → release the legs and
  let the safety system own motion.
- Every strafe and jump is **void-checked** (`VoidDetector.edgeAhead` /
  `isJumpLandingSafe`) so a combat manoeuvre can't walk the bot off a ledge.

Test (`deploy/runner/pvp_test.py`): first hit 4.3s, 18 damage, **0 freeze
windows, 136 blocks of movement** during the fight (vs. rooted before).

## Crash fix: mining-goto IndexOutOfBounds (#26)

A goto that ended at a wall needing a 1-block mine ("mining without a physics
leg") set an EMPTY executor path; `PathExecutor.getCurrentNode` then did
`path.get(size-1)` = `get(-1)`, throwing inside the entity tick and crashing the
whole client. Now guarded (returns null on empty path; callers already null-check).
