# 0.33.0

Ships the ranged-combat work that the mis-tagged 0.32.0 never actually published
(see note below), plus experimental groundwork for the block-space search rework.

## Bow aim via TrajectorySolver (the real 0.32.0 content)

`ShootArrowSimpleProjectileTask` (altoclef's combat shoot task, used by `@shoot`
and by `KillPlayerTask` at range) now aims through tungsten's vanilla-physics
`TrajectorySolver` instead of the old `g=0.006` closed form. Three things had to
line up:

- **Aim for the full-draw arc** (stable pitch target) — recomputing charge each
  tick swung the pitch and only settled at release. Took a stationary target from
  2/5 to **5/5** at 24 blocks.
- **Lead from self-tracked position deltas** — a walking remote player reports ~0
  `getVelocity()` on the client, so the task differences the target's position
  each tick instead.
- Weapon selection / when-to-shoot stay in altoclef (melee under 10 blocks, bow at
  range); only the aim moved. High-angle artillery keeps the closed-form lob.

New py4j primitive `targetKinematics(name)` (client-side pos / velocity / onGround).
Test: `deploy/runner/bow_altoclef_test.py` — standing **5/5** at 24 blocks.

## Experimental: SmartMoves block-space search (off by default)

Groundwork for the tungsten navigation rework (#1.6.1). A tungsten-native
`SmartMoves` neighbour generator (Traverse/Ascend/Descend/Parkour) behind the
`smartMoves` flag (`setTungstenSmartMoves(true)` / py4j). **Default OFF** — normal
navigation is unchanged. With the flag on, the terrain staircase course (A) now
routes via the async search; steep/gap terrain (B/C) is still in progress. This
is opt-in scaffolding, not a behaviour change for anyone who doesn't enable it.

## Note: why 0.33.0 and not 0.32.0

This repo builds many MC versions (1.16.5 … 1.21.11) that share one `vX.Y.Z` tag
namespace. A `v0.32.0` tag already existed from an older 1.21.1 build, so the
0.32.0 release for **1.21.11** was never published (running the un-scoped
`gradlew githubRelease` attached the 1.21.1 jar to the existing tag). Releases for
this branch must use `gradlew :1.21.11:githubRelease`. 0.33.0 is the next free tag
and carries the intended 1.21.11 content.
